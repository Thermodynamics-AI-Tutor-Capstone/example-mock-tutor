# Animated Grapher and written-work review

The local student-feedback experiment adds **Grapher** in the top bar and a **Check my work**
control in the chat composer. Graph checking is deliberately deferred.

## Drawing a diagram

Open `/grapher.html`, choose water or R-134a, select P-v, T-s, P-h, h-s, P-T or T-v, and enter
two independent properties per labeled state. Add processes in their physical order. Each
constant-property process must agree with its endpoint states; contradictory values are rejected.
The example button loads a clearly identified illustrative case, not inferred student givens.

The plot is generated by a fixed Python/Matplotlib program using the existing CoolProp-derived
local property tables. The browser animates the actual SVG strokes. **Play/Pause**, **Back**,
**Next**, **Restart** and **Speed** control the same ordered checklist displayed below the graph.
Reduced-motion preferences retain manual steps. Saved tutor replies can redraw the walkthrough.

Construction order:

1. Identify the fluid, givens and requested diagram.
2. Draw axes; label quantities, units and linear/logarithmic scales.
3. Add saturation boundaries (or the liquid-vapor coexistence curve on P-T).
4. Mark the critical point and valid phase regions.
5. Calculate, place and number the states.
6. Draw constrained process paths and direction arrows.
7. Recheck units, labels, phase locations, process direction and physical consistency.

P-T has no two-phase area: saturated liquid and vapor at the same temperature overlap, so
quality cannot be read from it. Solid-phase boundaries are not included. Dashed schematic or
throttling connectors do not establish intermediate real-process states. Plot area is not a
general heat/work calculation, especially on logarithmic axes. Near-critical interpolation has
finite accuracy. Follow the instructor's diagram convention and rubric; this is a construction
guide, not a guarantee of exam marks or learning effectiveness.

## Python setup

Use Python 3.10 or newer and install `scripts/grapher/requirements.txt`. Dependencies can be kept
within this checkout, without modifying global Python:

```powershell
python -m pip install --target .grapher-python -r scripts/grapher/requirements.txt
$env:KELVIN_PYTHON = (Get-Command python).Source
$env:PORT = '3301'
npm run dev
```

An ignored `.grapher-runtime.json` may instead provide a trusted local `pythonExecutable` path.
The renderer uses the checkout's `.grapher-python` directory when present. No Python, shell
commands, executable paths or filenames are accepted from diagram requests. Execution has a
timeout, output-size limit and bounded concurrency. Missing runtimes produce a useful error.
The Grapher does not call a model API and can be tested through `/dev-login`.

This implementation runs on the local Node server. The existing hosted Node/Vercel deployment
does not include a Python execution service; the tool is hidden and its route returns an explicit
unavailable response there. Do not claim a hosted deployment until Python hosting is configured
and checked. No production settings were changed.

## Check my work

Turn on **Check my work** and supply the problem and written working, either typed or uploaded.
Review and confirm the editable transcription of images/scanned pages before submitting.
The server adds a fixed instruction to inspect assumptions, equations, substitutions, units,
signs and arithmetic, using the existing calculation/property tools. It asks about unreadable
or missing information and explains the first incorrect step instead of inventing a grade.
The mode is saved with each submitted user message and can be switched off for normal tutoring.

Model/OCR review needs the application's configured providers. Local regression tests use a
mock provider; passing those tests verifies routing, validation and preserved context, not the
accuracy of live handwritten-solution assessment. Uploading a graph is not graph checking.

Future graph checking should compare confirmed axes, phase labels, critical point, states and
process paths against the problem, and clearly separate extraction uncertainty from physics errors.

## Verification

- `npm run grapher:test`: numerical/schema/renderer checks.
- `npm run grapher:browser`: animation, accessibility, multiple diagrams and responsive UI.
- `npm run grapher:api`: authenticated requests and actual Python rendering.
- `npm run check-work:test`: server-owned mode, uploaded-work validation and saved metadata.
- `npm run check-work:browser`: rejected-submission recovery without losing concurrent edits or uploads.
- Existing property, tutor/agent, equation-editor and attachment-preview suites remain relevant.
